Command와 Undo/Redo — 값으로 다루는 동작

실행·취소·재실행이 되는 편집 동작을 클래스 계층, std::variant, 상태 스냅숏, std::function 쌍, move_only_function으로 차례로 만들어 봅니다. 삭제를 정확히 되돌리는 조건, Redo 기록을 비우는 시점, 저장하는 바이트 수, 두 함수가 상태를 나눌 때의 비용을 비교합니다.

7편은 std::function과 std::move_only_function이 타입을 지운 값이라는 결론으로 끝났습니다. 이 글은 그 결론을 써서 실행·취소·재실행이 되는 동작을 값으로 다룹니다. 7편의 구현 세부는 몰라도 됩니다. "모양이 다른 람다들을 같은 타입의 값으로 담을 수 있다"는 사실 하나면 충분합니다.

동작을 객체로 만들어 나중에 실행하거나 되돌릴 수 있게 하는 설계를 Command(명령) 패턴이라고 합니다. 대표적인 쓰임이 실행 취소(Undo)와 재실행(Redo)입니다. 명령을 클래스 계층으로 만들지, std::variant나 함수 객체 같은 값으로 만들지, 명령 대신 상태를 통째로 저장할지 같은 예제로 비교합니다.

문제 상황

텍스트 편집기의 버퍼를 다룬다고 해 봅시다.

  • 버퍼는 문자열 하나입니다. 동작은 지금은 삽입과 삭제이고, 앞으로 늘어납니다.
  • Undo는 마지막 동작부터 되돌리고, Redo는 되돌린 동작을 다시 합니다.
  • Undo한 뒤 새 동작을 하면 Redo 기록은 버립니다. 갈라진 과거로 돌아갈 수는 없습니다.
  • 삭제 범위는 버퍼 끝을 넘을 수 있습니다. 그래도 되돌리면 원문이 정확히 돌아와야 합니다.
  • 긴 문서에서 작은 편집을 많이 해도, 기록이 편집마다 문서 크기만큼 늘면 안 됩니다.

순진한 구현

먼저 떠오르는 것은 편집 함수가 버퍼를 직접 고치고, 되돌릴 정보를 기록에 남기는 방식입니다. 기록의 종류는 enum으로 나누고 Undo는 switch로 역연산을 고릅니다.

cpp컴파일 검증됨 (g++ 14.2 · clang 18.1, C++20)
#include <cassert>
#include <cstddef>
#include <string>
#include <utility>
#include <vector>

class Editor {
 public:
  void insert(std::size_t pos, const std::string& s) {
    text_.insert(pos, s);
    log_.push_back({Kind::Insert, pos, s});
  }
  void erase(std::size_t pos, std::size_t count) {
    std::string removed = text_.substr(pos, count);
    text_.erase(pos, removed.size());
    log_.push_back({Kind::Erase, pos, std::move(removed)});
  }
  bool undo() {
    if (log_.empty()) return false;
    const Record& r = log_.back();
    switch (r.kind) {  // 동작이 늘면 이 switch를 고친다. Redo를 만들면 하나 더 생긴다
      case Kind::Insert: text_.erase(r.pos, r.text.size()); break;
      case Kind::Erase: text_.insert(r.pos, r.text); break;
    }
    log_.pop_back();
    return true;
  }
  const std::string& text() const { return text_; }

 private:
  enum class Kind { Insert, Erase };
  struct Record {
    Kind kind;
    std::size_t pos;
    std::string text;  // Insert는 넣은 글자, Erase는 지운 글자
  };
  std::string text_;
  std::vector<Record> log_;
};

int main() {
  Editor ed;
  ed.insert(0, "hello world");
  ed.erase(5, 6);
  assert(ed.text() == "hello");
  ed.undo();
  assert(ed.text() == "hello world");
}

작게는 잘 동작합니다. 문제는 동작이 늘 때 드러납니다.

  • "대문자로 바꾸기"를 더하면 Kind, Record의 필드, 편집 함수, Undo의 switch를 모두 고칩니다. Redo를 만들면 정방향 코드를 담은 switch가 하나 더 생기고, 편집 함수와 같은 로직이 두 곳에 있게 됩니다.
  • Record는 모든 동작의 필드를 합친 구조가 됩니다. 어떤 필드가 어떤 동작에서 의미 있는지는 주석으로만 알 수 있습니다.
  • 동작이 Editor 안에 갇혀 있습니다. 메뉴, 단축키, 매크로가 같은 동작을 "나중에 실행할 것"으로 들고 다닐 수 없습니다.

enum class를 default 없이 switch하면 -Wall이 빠뜨린 값을 경고하므로 빠뜨림 자체는 잡힙니다. 하지만 고칠 곳이 여러 곳에 흩어지는 문제는 그대로입니다.

패턴 적용

클래스 계층: 실행과 역연산을 한 객체에

Command 패턴은 동작 하나를 객체 하나로 만듭니다. 객체는 실행(execute)과 역연산(undo)을 함께 갖고, 되돌리는 데 필요한 정보도 직접 들고 있습니다. 위치 pos는 버퍼 길이 이하라고 가정합니다. 넘으면 std::string이 std::out_of_range 예외를 던집니다.

cpp컴파일 검증됨 (g++ 14.2 · clang 18.1, C++20)
#include <cassert>
#include <cstddef>
#include <memory>
#include <string>
#include <utility>
#include <vector>

using Buffer = std::string;

class Command {
 public:
  virtual ~Command() = default;
  virtual void execute(Buffer& buf) = 0;
  virtual void undo(Buffer& buf) = 0;
  virtual std::size_t stored_bytes() const = 0;  // 되돌리려고 들고 있는 글자 수
};

class Insert final : public Command {
 public:
  Insert(std::size_t pos, std::string text) : pos_(pos), text_(std::move(text)) {}
  void execute(Buffer& buf) override { buf.insert(pos_, text_); }
  void undo(Buffer& buf) override { buf.erase(pos_, text_.size()); }
  std::size_t stored_bytes() const override { return text_.size(); }

 private:
  std::size_t pos_;
  std::string text_;
};

class Erase final : public Command {
 public:
  Erase(std::size_t pos, std::size_t count) : pos_(pos), count_(count) {}
  void execute(Buffer& buf) override {
    removed_ = buf.substr(pos_, count_);  // 끝을 넘으면 남은 글자까지만 잘린다
    buf.erase(pos_, removed_.size());
  }
  void undo(Buffer& buf) override { buf.insert(pos_, removed_); }
  std::size_t stored_bytes() const override { return removed_.size(); }

 private:
  std::size_t pos_;
  std::size_t count_;  // 요청한 길이. 실제로 지운 길이는 removed_.size()
  std::string removed_;
};

Erase는 만들 때가 아니라 실행할 때 지운 글자를 저장합니다. 명령을 만든 뒤 실행하기 전에 버퍼가 바뀔 수 있고, Redo로 다시 실행할 때도 그때의 버퍼에서 읽어야 하기 때문입니다. 저장하는 것은 요청한 count_가 아니라 실제로 지운 글자입니다. substr는 범위가 끝을 넘으면 남은 만큼만 돌려주므로 removed_.size()가 실제로 지운 길이가 됩니다. buf.data() + pos_에서 count_만큼 복사하면 버퍼 밖을 읽습니다.

기록은 두 스택입니다. 실행한 명령(done_)과 되돌린 명령(undone_)을 오가며, 새 명령이 들어오면 undone_를 비웁니다.

cpp컴파일 검증됨 (g++ 14.2 · clang 18.1, C++20)
class History {
 public:
  void run(std::unique_ptr<Command> cmd, Buffer& buf) {
    cmd->execute(buf);
    done_.push_back(std::move(cmd));
    undone_.clear();  // 새 동작 뒤에는 Redo할 것이 없다
  }
  bool undo(Buffer& buf) {
    if (done_.empty()) return false;
    done_.back()->undo(buf);
    undone_.push_back(std::move(done_.back()));
    done_.pop_back();
    return true;
  }
  bool redo(Buffer& buf) {
    if (undone_.empty()) return false;
    undone_.back()->execute(buf);
    done_.push_back(std::move(undone_.back()));
    undone_.pop_back();
    return true;
  }
  std::size_t stored_bytes() const {
    std::size_t n = 0;
    for (const auto& c : done_) n += c->stored_bytes();
    for (const auto& c : undone_) n += c->stored_bytes();
    return n;
  }

 private:
  std::vector<std::unique_ptr<Command>> done_;
  std::vector<std::unique_ptr<Command>> undone_;
};

void check_history() {
  Buffer buf;
  History h;
  [[maybe_unused]] const bool empty_undo = h.undo(buf);
  [[maybe_unused]] const bool empty_redo = h.redo(buf);
  assert(!empty_undo && !empty_redo && buf.empty());  // 빈 기록에서는 아무 일도 없다

  h.run(std::make_unique<Insert>(0, "hello"), buf);
  h.run(std::make_unique<Insert>(5, " world"), buf);
  h.run(std::make_unique<Erase>(0, 6), buf);
  assert(buf == "world");
  h.undo(buf);
  assert(buf == "hello world");
  h.undo(buf);
  assert(buf == "hello");
  h.redo(buf);
  assert(buf == "hello world");

  h.run(std::make_unique<Erase>(5, 100), buf);  // 버퍼 끝을 넘는 삭제
  assert(buf == "hello");
  [[maybe_unused]] const bool stale_redo = h.redo(buf);
  assert(!stale_redo);  // 새 동작이 Redo 기록을 비웠다
  h.undo(buf);
  assert(buf == "hello world");  // 실제로 지운 6글자만 되돌린다
  while (h.undo(buf)) {
  }
  assert(buf.empty());
}

새 동작은 Command를 상속한 클래스 하나입니다. History도, 동작을 부르는 메뉴나 단축키 코드도 바뀌지 않습니다. 실행과 역연산이 한 클래스에 붙어 있으므로, 고칠 곳이 흩어지는 순진한 구현의 문제가 사라집니다.

대신 명령은 unique_ptr로 들고 다니고, 기록은 복사할 수 없습니다. 복사하려면 7편 순진한 구현의 clone()이 다시 필요합니다.

닫힌 집합이면 std::variant로

동작의 종류를 우리가 모두 정한다면 6편의 결론대로 std::variant를 쓸 수 있습니다. 명령은 평범한 구조체가 되고, 기록은 값의 vector가 됩니다.

cpp컴파일 검증됨 (g++ 14.2 · clang 18.1, C++20)
#include <cassert>
#include <cstddef>
#include <string>
#include <utility>
#include <variant>
#include <vector>

using Buffer = std::string;

struct Insert {
  std::size_t pos;
  std::string text;
};
struct Erase {
  std::size_t pos;
  std::size_t count;
  std::string removed{};  // apply가 실제로 지운 글자를 채운다
};
using Command = std::variant<Insert, Erase>;

template <class... Ts>
struct overloaded : Ts... {
  using Ts::operator()...;
};

void apply(Command& cmd, Buffer& buf) {
  std::visit(overloaded{
                 [&](Insert& c) { buf.insert(c.pos, c.text); },
                 [&](Erase& c) {
                   c.removed = buf.substr(c.pos, c.count);
                   buf.erase(c.pos, c.removed.size());
                 },
             },
             cmd);
}

void revert(const Command& cmd, Buffer& buf) {
  std::visit(overloaded{
                 [&](const Insert& c) { buf.erase(c.pos, c.text.size()); },
                 [&](const Erase& c) { buf.insert(c.pos, c.removed); },
             },
             cmd);
}

class History {
 public:
  void run(Command cmd, Buffer& buf) {
    apply(cmd, buf);
    done_.push_back(std::move(cmd));
    undone_.clear();
  }
  bool undo(Buffer& buf) {
    if (done_.empty()) return false;
    revert(done_.back(), buf);
    undone_.push_back(std::move(done_.back()));
    done_.pop_back();
    return true;
  }
  bool redo(Buffer& buf) {
    if (undone_.empty()) return false;
    apply(undone_.back(), buf);
    done_.push_back(std::move(undone_.back()));
    undone_.pop_back();
    return true;
  }

 private:
  std::vector<Command> done_;
  std::vector<Command> undone_;
};

int main() {
  Buffer buf;
  History h;
  h.run(Insert{.pos = 0, .text = "hello world"}, buf);
  h.run(Erase{.pos = 5, .count = 100}, buf);
  assert(buf == "hello");

  History copy = h;  // 값이므로 기록째 복사된다
  Buffer other = buf;
  copy.undo(other);
  assert(other == "hello world");

  h.undo(buf);  // 원본 기록은 복사본과 따로 움직인다
  assert(buf == "hello world");
  h.run(Insert{.pos = 0, .text = ">"}, buf);
  [[maybe_unused]] const bool stale_redo = h.redo(buf);
  assert(!stale_redo && buf == ">hello world");
}

overloaded는 6편의 관용구입니다. apply는 Erase의 removed를 채워야 하므로 const가 아닌 참조로 받고, revert는 읽기만 하므로 const로 받습니다. 새 동작을 더하면 std::visit이 빠뜨린 람다를 컴파일 오류로 알려 줍니다. 순진한 구현의 switch처럼 고칠 곳은 두 함수에 나뉘지만, 각 동작의 자료는 구조체마다 따로 있습니다.

명령 대신 상태를 저장: 스냅숏(Memento)

역연산을 아예 쓰지 않는 길도 있습니다. 편집하기 전 버퍼를 통째로 저장했다가, Undo 때 그 상태로 돌아가는 방식입니다. 객체의 내부 상태를 밖에 저장해 두었다가 복원하는 설계를 Memento(스냅숏) 패턴이라고 합니다.

cpp컴파일 검증됨 (g++ 14.2 · clang 18.1, C++20)
class SnapshotHistory {
 public:
  template <class Edit>
  void run(Edit edit, Buffer& buf) {
    Buffer before = buf;  // 고치기 전 상태를 통째로 복사한다
    edit(buf);
    done_.push_back(std::move(before));
    undone_.clear();
  }
  bool undo(Buffer& buf) {
    if (done_.empty()) return false;
    undone_.push_back(std::move(buf));
    buf = std::move(done_.back());
    done_.pop_back();
    return true;
  }
  bool redo(Buffer& buf) {
    if (undone_.empty()) return false;
    done_.push_back(std::move(buf));
    buf = std::move(undone_.back());
    undone_.pop_back();
    return true;
  }
  std::size_t stored_bytes() const {
    std::size_t n = 0;
    for (const auto& s : done_) n += s.size();
    for (const auto& s : undone_) n += s.size();
    return n;
  }

 private:
  std::vector<Buffer> done_;
  std::vector<Buffer> undone_;
};

void compare_memory() {
  const Buffer doc(10'000, 'x');
  Buffer a = doc;
  Buffer b = doc;
  History commands;
  SnapshotHistory snapshots;
  for (std::size_t i = 0; i < 100; ++i) {
    commands.run(std::make_unique<Insert>(i, "y"), a);
    snapshots.run([i](Buffer& buf) { buf.insert(i, "y"); }, b);
  }
  assert(a == b);
  assert(commands.stored_bytes() == 100);  // 넣은 글자 1개씩
  // i번째 스냅숏은 편집 전 버퍼 전체로 10000 + i 글자다
  assert(snapshots.stored_bytes() == 100 * 10'000 + 99 * 100 / 2);

  while (commands.undo(a)) {
  }
  while (snapshots.undo(b)) {
  }
  assert(a == doc && b == doc);
}

int main() {
  check_history();
  compare_memory();
}

1만 글자 문서에 한 글자씩 100번 넣었을 때 명령 기록은 100바이트를, 스냅숏 기록은 약 100만 바이트를 저장합니다. 크기는 sizeof가 아니라 저장한 글자 수로 쟀습니다. sizeof(std::string)은 내용 길이와 관계없이 고정된 객체 크기라서, 힙에 둔 글자를 세지 않습니다.

스냅숏의 장점은 역연산이 필요 없다는 것입니다. 편집 함수에 버그가 있어도 Undo는 정확히 이전 상태로 돌아갑니다. 동작을 추가할 때도 기록 쪽은 고칠 것이 없습니다. 대신 편집할 때마다 버퍼 전체를 복사하므로 시간과 메모리가 문서 크기에 비례합니다. 상태가 작거나, 역연산을 쓰기 어려운 동작(예: 이미지 필터)일 때 맞습니다. 바뀌지 않은 부분을 스냅숏끼리 나눠 쓰는 자료 구조를 쓰면 이 비용을 줄일 수 있지만 이 글의 범위를 넘습니다.

실행과 역연산의 상태 공유같은 객체의 멤버같은 구조체의 필드두 람다 사이에 따로 해결해당 없음

명령 방식 셋은 편집 크기에 비례해 저장하지만, 역연산이 틀리면 Undo가 조용히 틀립니다. 스냅숏은 반대로 정확성을 공짜로 얻고 메모리를 냅니다. 스냅숏 열의 "편집 전 버퍼 전체"는 위 compare_memory의 두 번째 assert가 근거입니다.

std::function 쌍은 다음 절에서 만듭니다. 마지막 행이 이 방식의 실제 비용입니다. 계층과 variant에서는 Erase가 지운 글자를 멤버나 필드 하나에 두고 execute와 undo가 함께 봅니다. 함수 두 개로 나누면 이 상태를 어디에 둘지 따로 정해야 합니다.

현대 C++ 대안

C++11: std::function 쌍

동작 집합이 열려 있고, 동작마다 클래스를 만들기는 번거롭다면 실행과 역연산을 std::function 두 개로 담습니다. 새 동작은 이 쌍을 돌려주는 함수 하나입니다.

지운 글자를 두 람다가 함께 봐야 하는 문제는 두 가지로 풀 수 있습니다. 하나는 std::shared_ptr<std::string>을 두 람다가 함께 캡처하는 것입니다. 그러면 할당이 하나 늘고, 기록을 복사해도 복사본이 원본과 같은 문자열을 가리킵니다. 복사본에서 Redo하면 원본의 Undo 정보가 바뀝니다. 여기서는 다른 하나를 고릅니다. 명령을 만들 때 지울 글자를 미리 읽어 두면, 실행 람다는 길이만, 역연산 람다는 글자만 가지면 됩니다.

cpp컴파일 검증됨 (g++ 14.2 · clang 18.1, C++20)
#include <cassert>
#include <cctype>
#include <cstddef>
#include <functional>
#include <string>
#include <utility>
#include <vector>

using Buffer = std::string;

struct Action {
  std::function<void(Buffer&)> apply;
  std::function<void(Buffer&)> revert;
};

Action insert_text(std::size_t pos, std::string text) {
  const std::size_t n = text.size();  // 첫 람다가 text를 옮기기 전에 구한다
  return {[pos, text = std::move(text)](Buffer& buf) { buf.insert(pos, text); },
          [pos, n](Buffer& buf) { buf.erase(pos, n); }};
}

// 지울 글자를 만들 때 읽어 둔다. 두 람다가 나눠 가질 상태가 없다.
Action erase_text(const Buffer& current, std::size_t pos, std::size_t count) {
  std::string removed = current.substr(pos, count);
  const std::size_t n = removed.size();
  return {[pos, n](Buffer& buf) { buf.erase(pos, n); },
          [pos, removed = std::move(removed)](Buffer& buf) { buf.insert(pos, removed); }};
}

// 새 동작은 Action을 돌려주는 함수 하나다. History는 바뀌지 않는다.
Action upper_case(const Buffer& current, std::size_t pos, std::size_t count) {
  std::string before = current.substr(pos, count);
  std::string after = before;
  for (char& ch : after) ch = static_cast<char>(std::toupper(static_cast<unsigned char>(ch)));
  return {[pos, after = std::move(after)](Buffer& buf) { buf.replace(pos, after.size(), after); },
          [pos, before = std::move(before)](Buffer& buf) { buf.replace(pos, before.size(), before); }};
}

class History {
 public:
  void run(Action action, Buffer& buf) {
    action.apply(buf);
    done_.push_back(std::move(action));
    undone_.clear();
  }
  bool undo(Buffer& buf) {
    if (done_.empty()) return false;
    done_.back().revert(buf);
    undone_.push_back(std::move(done_.back()));
    done_.pop_back();
    return true;
  }
  bool redo(Buffer& buf) {
    if (undone_.empty()) return false;
    undone_.back().apply(buf);
    done_.push_back(std::move(undone_.back()));
    undone_.pop_back();
    return true;
  }

 private:
  std::vector<Action> done_;
  std::vector<Action> undone_;
};

int main() {
  Buffer buf;
  History h;
  h.run(insert_text(0, "hello world"), buf);
  h.run(upper_case(buf, 0, 5), buf);
  assert(buf == "HELLO world");
  h.run(erase_text(buf, 5, 100), buf);  // 만들 때와 실행할 때의 버퍼가 같다
  assert(buf == "HELLO");

  h.undo(buf);
  assert(buf == "HELLO world");
  h.undo(buf);
  assert(buf == "hello world");
  h.redo(buf);
  assert(buf == "HELLO world");
  while (h.undo(buf)) {
  }
  assert(buf.empty());
}

이 방식의 조건은 명령을 만들 때의 버퍼와 처음 실행할 때의 버퍼가 같아야 한다는 것입니다. 그래서 erase_text가 버퍼를 인자로 받고, h.run(erase_text(buf, …), buf)처럼 만들자마자 실행합니다. 명령을 미리 만들어 두었다가 나중에 실행하는 매크로에는 맞지 않습니다. 그런 경우는 실행할 때 읽어야 하므로, 아래처럼 두 동작을 한 객체로 합칩니다.

insert_text에서 n을 먼저 구한 것도 같은 종류의 함정입니다. 중괄호 초기화 목록은 앞에서부터 차례로 평가되므로, 두 번째 람다에서 text.size()를 캡처하면 이미 옮겨진 text의 길이를 읽습니다. 옮겨진 문자열의 값은 정해져 있지 않고, 검증한 두 환경에서는 빈 문자열이라 Undo가 아무것도 지우지 않았습니다.

std::function은 담은 대상을 복사할 수 있어야 합니다. 복사할 수 없는 unique_ptr을 캡처한 람다는 담을 수 없어서 아래 코드는 컴파일되지 않습니다. libstdc++에서는 std::function target must be copy-constructible이라는 오류가 납니다.

cpp컴파일 오류 예시
#include <functional>
#include <memory>
#include <string>

using Buffer = std::string;

std::function<void(Buffer&)> paste(std::unique_ptr<const std::string> text) {
  return [text = std::move(text)](Buffer& buf) { buf += *text; };  // 람다를 복사할 수 없다
}

C++23: std::move_only_function으로 한 객체에

std::move_only_function은 이동만 되는 대상도 담습니다. 실행과 역연산을 단계 인자 하나로 구분하는 호출 가능 객체로 합치면, 지운 글자를 람다 자신의 멤버로 두고 실행할 때 채울 수 있습니다. 상태를 나눌 상대가 없어집니다.

cpp컴파일 검증됨 (g++ 14.2 · clang 18.1, C++23)
#include <cassert>
#include <cstddef>
#include <functional>
#include <memory>
#include <string>
#include <type_traits>
#include <utility>
#include <vector>

using Buffer = std::string;
enum class Step { Apply, Revert };
using Action = std::move_only_function<void(Buffer&, Step)>;

Action erase_text(std::size_t pos, std::size_t count) {
  return [pos, count, removed = std::string{}](Buffer& buf, Step step) mutable {
    if (step == Step::Apply) {
      removed = buf.substr(pos, count);  // 실행할 때 읽는다
      buf.erase(pos, removed.size());
    } else {
      buf.insert(pos, removed);
    }
  };
}

// 붙여넣을 큰 내용을 복사하지 않고 소유권째 넘겨받는다.
Action paste(std::size_t pos, std::unique_ptr<const std::string> text) {
  return [pos, text = std::move(text)](Buffer& buf, Step step) {
    if (step == Step::Apply) {
      buf.insert(pos, *text);
    } else {
      buf.erase(pos, text->size());
    }
  };
}

int main() {
  static_assert(!std::is_copy_constructible_v<Action>);

  Buffer buf = "hello";
  std::vector<Action> done;
  done.push_back(paste(5, std::make_unique<const std::string>(" world")));
  done.push_back(erase_text(0, 100));  // 만들 때는 버퍼를 보지 않는다
  for (Action& action : done) action(buf, Step::Apply);
  assert(buf.empty());

  for (auto it = done.rbegin(); it != done.rend(); ++it) (*it)(buf, Step::Revert);
  assert(buf == "hello");
}

두 동작을 한 객체로 합치는 것 자체는 std::function으로도 됩니다. removed 같은 상태는 복사할 수 있기 때문입니다. move_only_function이 더하는 것은 두 가지입니다. paste처럼 이동만 되는 자원을 캡처할 수 있고, 시그니처의 const 한정자를 지킵니다. std::function의 호출 연산자는 const인데도 mutable 람다를 부를 수 있습니다. move_only_function<void(Buffer&, Step) const>로 선언하면 erase_text의 mutable 람다는 컴파일되지 않습니다.

대신 기록을 복사할 수 없는 것은 클래스 계층과 같습니다. 단계 인자는 if로 나뉘므로 실행과 역연산이 한 람다 안에서 섞입니다. 동작이 커지면 람다 대신 apply·revert 멤버 함수를 가진 작은 구조체를 만들어 담는 편이 읽기 쉽습니다.

std::move_only_function은 표준 라이브러리 구현에 따라 지원 시점이 다릅니다. libstdc++는 GCC 12부터 제공합니다. libc++의 C++23 지원 표에는 이 글을 쓰는 시점에 해당 제안서가 완료로 적혀 있지 않고, 검증할 때 쓴 Apple clang 21의 libc++에도 없었습니다.

정리

  • 동작이 늘어나는 편집 기록은 실행과 역연산을 한 단위로 묶습니다. 고칠 곳이 흩어지지 않습니다.
  • 삭제 같은 동작은 실행할 때 실제로 지운 것을 저장합니다. 요청한 범위를 저장하면 끝을 넘는 삭제에서 Undo가 틀립니다.
  • 새 동작을 하면 Redo 기록을 비웁니다. 빈 기록의 Undo·Redo는 아무 일도 하지 않게 합니다.
  • 동작 집합이 닫혀 있고 기록을 복사해야 하면 variant, 열려 있으면 클래스 계층이나 함수 객체를 씁니다. 함수 두 개로 나누면 공유 상태를 먼저 정합니다.
  • 상태가 작거나 역연산이 어려우면 스냅숏이 가장 단순합니다. 저장량은 버퍼 크기 × 편집 횟수로 셉니다.
  • 실제 편집기는 연속 입력 여러 글자를 명령 하나로 합칩니다. 이를 병합(coalescing)이라고 하며, 새 명령이 들어올 때 직전 명령과 합칠 수 있는지 묻는 함수를 하나 더 두는 식으로 만듭니다.

다음 편에서는 구현을 헤더 밖으로 숨겨 컴파일 의존을 끊는 Pimpl을 다룹니다.
