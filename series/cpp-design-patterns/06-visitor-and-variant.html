Visitor와 std::variant — 이중 디스패치의 대안

타입 집합이 닫혀 있을 때 연산을 타입 밖에 두는 두 방법, 클래식 Visitor와 std::variant를 같은 예제로 비교합니다. 새 타입과 새 연산의 비용, 두 값의 조합, 조용한 변환과 값 없는 상태 같은 std::visit의 함정, 재귀 구조까지 확인하고 고르는 기준을 정리합니다.

타입 집합이 닫혀 있을 때, 클래식 Visitor와 std::variant + std::visit 가운데 무엇이 나을까요? 이 글은 같은 문제를 두 방식으로 풀고, 새 타입과 새 연산을 추가하는 비용이 어떻게 달라지는지 비교합니다. std::visit에서 빠뜨린 타입을 컴파일러가 찾아 주는 조건과, 찾아 주지 못하는 경우도 확인합니다.

문제 상황

그림 편집기의 도형을 다룬다고 해 봅시다.

  • 도형은 원, 사각형, 삼각형 세 가지이고 좀처럼 늘지 않는다.
  • 연산은 계속 늘어난다. 넓이, 설명 문자열, 파일 저장, 화면 출력이 차례로 생긴다.
  • 도형 클래스가 출력 형식이나 화면 라이브러리를 알게 하고 싶지 않다.
  • 도형을 추가했는데 어떤 연산이 빠졌다면 컴파일할 때 알고 싶다.

연산마다 가상 함수를 하나씩 더하면 마지막 조건은 순수 가상 함수로 지킬 수 있습니다. 대신 연산이 생길 때마다 모든 도형 클래스를 고쳐야 하고, 도형이 출력 형식까지 알게 됩니다. 그래서 연산을 도형 밖으로 빼려고 합니다.

순진한 구현

밖에서 실제 타입을 알아내는 가장 쉬운 방법은 dynamic_cast를 차례로 시도하는 것입니다.

cpp컴파일 검증됨 (g++ 14.2 · clang 18.1, C++20)
#include <cassert>
#include <string>

struct Shape {
  virtual ~Shape() = default;
};
struct Circle final : Shape {};
struct Rect final : Shape {};
struct Triangle final : Shape {};

std::string name(const Shape& shape) {
  if (dynamic_cast<const Circle*>(&shape)) return "circle";
  if (dynamic_cast<const Rect*>(&shape)) return "rect";
  return "unknown";  // Triangle을 빠뜨렸지만 컴파일된다
}

int main() {
  assert(name(Circle{}) == "circle");
  assert(name(Rect{}) == "rect");
  assert(name(Triangle{}) == "unknown");  // 실행해야 드러난다
}

도형을 추가해도 컴파일러는 이 함수를 고치라고 알려 주지 않습니다. 검사 순서도 문제입니다. 상속 관계인 두 타입 가운데 부모를 먼저 검사하면 자식의 분기에는 닿지 못합니다. 모르는 타입이 왔을 때 무엇을 할지도 함수마다 따로 정해야 합니다.

패턴 적용

클래식 Visitor: 두 번의 가상 호출

Visitor는 연산을 객체로 만들고, 타입마다 visit 함수를 하나씩 둡니다. 도형은 "나를 방문하라"는 accept 하나만 가집니다.

cpp컴파일 검증됨 (g++ 14.2 · clang 18.1, C++20)
#include <cassert>
#include <memory>
#include <numbers>
#include <string>
#include <vector>

class Circle;
class Rect;
class Triangle;

class ShapeVisitor {
 public:
  virtual ~ShapeVisitor() = default;
  virtual void visit(const Circle& circle) = 0;
  virtual void visit(const Rect& rect) = 0;
  virtual void visit(const Triangle& triangle) = 0;
};

class Shape {
 public:
  virtual ~Shape() = default;
  virtual void accept(ShapeVisitor& visitor) const = 0;
};

class Circle final : public Shape {
 public:
  explicit Circle(double radius) : radius_(radius) {}
  double radius() const { return radius_; }
  void accept(ShapeVisitor& visitor) const override { visitor.visit(*this); }

 private:
  double radius_;
};

class Rect final : public Shape {
 public:
  Rect(double width, double height) : width_(width), height_(height) {}
  double width() const { return width_; }
  double height() const { return height_; }
  void accept(ShapeVisitor& visitor) const override { visitor.visit(*this); }

 private:
  double width_;
  double height_;
};

class Triangle final : public Shape {
 public:
  Triangle(double base, double height) : base_(base), height_(height) {}
  double base() const { return base_; }
  double height() const { return height_; }
  void accept(ShapeVisitor& visitor) const override { visitor.visit(*this); }

 private:
  double base_;
  double height_;
};

accept의 본문은 모두 같은 글자지만 베이스로 올릴 수 없습니다. Circle::accept 안에서는 *this의 정적 타입이 const Circle이라서 visit(const Circle&)가 선택됩니다. 베이스에서는 *this가 const Shape이므로 고를 visit이 없습니다.

연산은 이 인터페이스를 구현하는 클래스입니다. visit이 값을 돌려주지 않으므로 결과는 멤버에 담습니다.

cpp컴파일 검증됨 (g++ 14.2 · clang 18.1, C++20)
class AreaVisitor final : public ShapeVisitor {
 public:
  void visit(const Circle& c) override { area_ = std::numbers::pi * c.radius() * c.radius(); }
  void visit(const Rect& r) override { area_ = r.width() * r.height(); }
  void visit(const Triangle& t) override { area_ = t.base() * t.height() / 2; }
  double area() const { return area_; }

 private:
  double area_ = 0;
};

class NameVisitor final : public ShapeVisitor {
 public:
  void visit(const Circle&) override { name_ = "circle"; }
  void visit(const Rect&) override { name_ = "rect"; }
  void visit(const Triangle&) override { name_ = "triangle"; }
  const std::string& name() const { return name_; }

 private:
  std::string name_;
};

// 호출하는 쪽은 Visitor를 몰라도 되게 감싼다.
double area(const Shape& shape) {
  AreaVisitor visitor;
  shape.accept(visitor);
  return visitor.area();
}

std::string name(const Shape& shape) {
  NameVisitor visitor;
  shape.accept(visitor);
  return visitor.name();
}

int main() {
  std::vector<std::unique_ptr<Shape>> shapes;
  shapes.push_back(std::make_unique<Circle>(2.0));
  shapes.push_back(std::make_unique<Rect>(2.0, 3.0));
  shapes.push_back(std::make_unique<Triangle>(4.0, 3.0));

  assert(area(*shapes[0]) == 4 * std::numbers::pi);
  assert(area(*shapes[1]) == 6.0);
  assert(area(*shapes[2]) == 6.0);
  assert(name(*shapes[0]) == "circle");
  assert(name(*shapes[1]) == "rect");
  assert(name(*shapes[2]) == "triangle");
}

가상 호출이 두 번 일어납니다. accept는 도형의 실제 타입으로, visit은 연산의 실제 타입으로 정해집니다. 이처럼 실행할 함수가 두 객체의 실제 타입으로 정해지는 것을 이중 디스패치(double dispatch)라고 합니다. C++의 가상 함수는 객체 하나의 타입만 보고 고르므로 두 번에 나눈 것입니다.

새 연산은 새 클래스 하나로 끝나고 도형은 바뀌지 않습니다. 도형을 추가하면 ShapeVisitor에 순수 가상 함수가 하나 늘고, 모든 Visitor가 추상 클래스가 되어 객체를 만드는 곳에서 컴파일 오류가 납니다. 빠뜨린 연산을 컴파일러가 찾아 주는 셈입니다.

구체 클래스에는 final을 붙였습니다. final이 아닌 Circle을 상속한 클래스가 accept를 다시 정의하지 않으면, 오류 없이 Circle로 방문되기 때문입니다.

같은 기능을 std::variant로

std::variant(C++17)는 정해진 타입 가운데 하나의 값을 담는 타입입니다. 담을 수 있는 타입 하나하나를 대안(alternative)이라고 합니다. 공통 베이스도 accept도 필요 없습니다.

cpp컴파일 검증됨 (g++ 14.2 · clang 18.1, C++20)
#include <cassert>
#include <numbers>
#include <string>
#include <variant>
#include <vector>

struct Circle { double radius; };
struct Rect { double width, height; };
struct Triangle { double base, height; };
using Shape = std::variant<Circle, Rect, Triangle>;

// 람다 여러 개의 operator()를 한 객체의 오버로드로 모은다.
template <class... Ts>
struct overloaded : Ts... {
  using Ts::operator()...;
};

double area(const Shape& shape) {
  return std::visit(
      overloaded{
          [](const Circle& c) { return std::numbers::pi * c.radius * c.radius; },
          [](const Rect& r) { return r.width * r.height; },
          [](const Triangle& t) { return t.base * t.height / 2; },
      },
      shape);
}

std::string name(const Shape& shape) {
  return std::visit<std::string>(  // 반환 타입 지정은 C++20
      overloaded{
          [](const Circle&) { return "circle"; },
          [](const Rect&) { return "rect"; },
          [](const Triangle&) { return "triangle"; },
      },
      shape);
}

int main() {
  const std::vector<Shape> shapes{Circle{2.0}, Rect{2.0, 3.0}, Triangle{4.0, 3.0}};
  assert(area(shapes[0]) == 4 * std::numbers::pi);
  assert(area(shapes[1]) == 6.0);
  assert(area(shapes[2]) == 6.0);
  assert(name(shapes[0]) == "circle");
  assert(name(shapes[1]) == "rect");
  assert(name(shapes[2]) == "triangle");

  std::vector<Shape> copy = shapes;  // 값이므로 그대로 복사된다
  copy[0] = Rect{1.0, 1.0};
  assert(area(copy[0]) == 1.0);
  assert(area(shapes[0]) == 4 * std::numbers::pi);
}

overloaded는 관용구입니다. 람다 타입을 모두 상속하고, using으로 각각의 operator()를 끌어와 오버로드 후보로 만듭니다. overloaded{…}에서 템플릿 인자를 적지 않은 것은 C++20의 집합체 클래스 템플릿 인자 추론(CTAD) 덕분입니다. C++17에서는 추론 안내(deduction guide) 한 줄을 더 씁니다.

cpp일부 발췌 · 검증 제외
// C++17에서만 필요하다
template <class... Ts>
overloaded(Ts...) -> overloaded<Ts...>;

std::visit은 모든 대안에 대해 호출식이 올바를 것을 요구합니다. 삼각형을 빠뜨리면 실행하기 전에 막힙니다.

cpp컴파일 오류 예시
#include <variant>

struct Circle { double radius; };
struct Rect { double width, height; };
struct Triangle { double base, height; };

template <class... Ts>
struct overloaded : Ts... {
  using Ts::operator()...;
};

double area(const std::variant<Circle, Rect, Triangle>& shape) {
  return std::visit(
      overloaded{
          [](const Circle& c) { return 3.14 * c.radius * c.radius; },
          [](const Rect& r) { return r.width * r.height; },
          // Triangle이 없다
      },
      shape);
}

순진한 구현의 실수가 컴파일 오류로 바뀌었습니다. 다만 오류는 <variant> 내부에서 나서 길고, 어느 대안이 빠졌는지 찾으려면 메시지를 읽어야 합니다.

타입과 연산을 모두 쉽게 추가하기는 어렵습니다. 이를 표현 문제(expression problem)라고 합니다. 멤버 가상 함수는 타입 추가가, Visitor와 variant는 연산 추가가 쉽습니다. 이 축에서 Visitor와 variant는 같은 편입니다. 둘의 차이는 저장 방식과 헤더 의존, 타입들이 이미 상속 계층인지에 있습니다.

성능은 한쪽이 항상 빠르다고 말할 수 없습니다. 표준은 variant 하나를 방문할 때 호출 대상을 고르는 시간이 대안 수와 무관하다고 정합니다. 둘 이상일 때는 요구가 없습니다. variant는 객체마다 힙 할당을 하지 않아도 되지만, 대안 하나만 크면 모든 값이 그만큼 커집니다. 중요하다면 실제 데이터로 재야 합니다.

두 방식을 모두 쓰지 말아야 할 때도 있습니다.

  • 플러그인처럼 타입이 바깥에서 늘어난다면 멤버 가상 함수나 7편의 type erasure가 맞습니다. 모든 타입을 미리 적을 수 없기 때문입니다.
  • 연산이 한두 개로 고정이면 멤버 가상 함수가 짧습니다.
  • 상태만 다르고 자료가 같다면 enum class와 switch로 충분합니다.
  • 클래스 계층이 이미 있고 고칠 수 없다면 accept를 넣을 수 없습니다. 값으로 variant에 담으려면 계층을 소유하는 코드를 다시 설계해야 합니다. std::variant<const Circle*, const Rect*>처럼 포인터를 대안으로 둘 수도 있지만, 수명은 따로 관리하고 베이스 포인터만 있다면 실제 타입을 먼저 알아내야 합니다.

현대 C++ 대안

C++20: 조용한 변환을 컴파일 오류로

빠뜨린 대안을 늘 찾아 주는 것은 아닙니다. 람다의 매개변수로 변환할 수 있으면 올바른 호출이기 때문입니다.

cpp컴파일 검증됨 (g++ 14.2 · clang 18.1, C++20)
#include <cassert>
#include <string>
#include <variant>

template <class... Ts>
struct overloaded : Ts... {
  using Ts::operator()...;
};

using Value = std::variant<int, double, std::string>;

std::string kind(const Value& value) {
  return std::visit<std::string>(
      overloaded{
          [](double) { return "double"; },
          [](const std::string&) { return "string"; },
          // int를 빠뜨렸지만 double로 변환되어 컴파일된다
      },
      value);
}

int main() {
  assert(kind(1.5) == "double");
  assert(kind(std::string{"a"}) == "string");
  assert(kind(1) == "double");  // 조용한 오답
}

정확히 맞는 람다가 없을 때만 선택되는 포괄 람다를 두고, 그 안에서 컴파일을 멈추면 막을 수 있습니다. 정확히 일치하는 템플릿이 변환이 필요한 double보다 우선합니다. C++20 템플릿 람다를 쓰면 타입에 이름을 붙이기 쉽습니다.

cpp컴파일 오류 예시
#include <string>
#include <variant>

template <class... Ts>
struct overloaded : Ts... {
  using Ts::operator()...;
};

template <class T>
inline constexpr bool unhandled_alternative = false;

void check(const std::variant<int, double, std::string>& value) {
  std::visit(
      overloaded{
          [](double) {},
          [](const std::string&) {},
          []<class T>(const T&) { static_assert(unhandled_alternative<T>); },
      },
      value);
}

포괄 람다의 매개변수는 const T&로 둡니다. auto&&로 쓰면 const가 아닌 variant를 방문할 때 문제가 됩니다. 이때 값은 double&로 전달됩니다. 다른 람다가 const double&로 받는다면 auto&&가 더 잘 맞아, 이미 처리한 타입까지 포괄 람다로 갑니다. const T&라면 동점이 되고, 동점에서는 템플릿이 아닌 쪽이 선택됩니다. 단, 값을 고치려고 받는 double&나 값으로 받는 double은 어느 쪽이든 먼저 선택됩니다.

반대로 아무 일도 하지 않는 [](const auto&) {}는 빠뜨림 검사를 끄는 것과 같습니다. 새 대안이 생겨도 조용히 그쪽으로 갑니다. "나머지는 무시한다"가 정말 요구 사항일 때만 씁니다.

C++17: 두 값의 조합

std::visit은 variant를 여러 개 받습니다. 두 도형이 겹치는지처럼 두 자료의 타입에 따라 달라지는 연산을 직접 쓸 수 있습니다. 클래식 Visitor로 같은 일을 하려면, 첫 도형의 타입을 기억한 Visitor로 둘째 도형을 다시 방문해야 합니다.

cpp컴파일 검증됨 (g++ 14.2 · clang 18.1, C++20)
#include <algorithm>
#include <cassert>
#include <variant>

struct Circle { double x, y, radius; };
struct Box { double left, top, right, bottom; };  // left <= right, top <= bottom
using Shape = std::variant<Circle, Box>;

template <class... Ts>
struct overloaded : Ts... {
  using Ts::operator()...;
};

bool hit(const Circle& a, const Circle& b) {
  const double dx = a.x - b.x, dy = a.y - b.y, sum = a.radius + b.radius;
  return dx * dx + dy * dy <= sum * sum;
}
bool hit(const Box& a, const Box& b) {
  return a.left <= b.right && b.left <= a.right && a.top <= b.bottom && b.top <= a.bottom;
}
bool hit(const Circle& c, const Box& b) {
  const double dx = c.x - std::clamp(c.x, b.left, b.right);
  const double dy = c.y - std::clamp(c.y, b.top, b.bottom);
  return dx * dx + dy * dy <= c.radius * c.radius;
}

bool overlaps(const Shape& a, const Shape& b) {
  return std::visit(
      overloaded{
          [](const Circle& x, const Circle& y) { return hit(x, y); },
          [](const Box& x, const Box& y) { return hit(x, y); },
          [](const Circle& x, const Box& y) { return hit(x, y); },
          [](const Box& x, const Circle& y) { return hit(y, x); },
      },
      a, b);
}

int main() {
  [[maybe_unused]] const Shape circle = Circle{0, 0, 1};
  [[maybe_unused]] const Shape touching = Box{1, -1, 3, 1};
  [[maybe_unused]] const Shape corner = Box{0.9, 0.9, 2, 2};  // 원의 외접 사각형과만 겹친다
  assert(overlaps(circle, touching) && overlaps(touching, circle));
  assert(!overlaps(circle, corner) && !overlaps(corner, circle));
  assert(overlaps(circle, Circle{2, 0, 1}) && !overlaps(circle, Circle{2.1, 0, 1}));
  [[maybe_unused]] const Shape box = Box{0, 0, 2, 2};
  assert(overlaps(box, corner) && overlaps(box, Box{2, 2, 3, 3}));
  assert(!overlaps(box, Box{3, 0, 4, 2}) && !overlaps(box, Box{-2, 0, -1, 2}));
  assert(!overlaps(box, Box{0, 3, 2, 4}) && !overlaps(box, Box{0, -2, 2, -1}));
}

네 조합 가운데 하나를 지우면 컴파일되지 않습니다. 대신 조합은 대안 수의 제곱으로 늘어납니다. 열 가지 도형이면 백 가지이므로, 공통 표현(예: 다각형)으로 바꿔 계산하는 편이 나을 수 있습니다.

C++17: 재귀 구조와 값 없는 상태

Visitor가 자주 쓰이는 곳은 수식이나 문서 같은 트리입니다. variant는 자기 자신을 값으로 담을 수 없으므로 간접 저장이 필요합니다. std::vector는 C++17부터 불완전 타입(incomplete type)을 원소로 선언할 수 있어서 이 자리에 쓸 수 있습니다.

cpp컴파일 검증됨 (g++ 14.2 · clang 18.1, C++20)
#include <cassert>
#include <variant>
#include <vector>

struct Sum;
using Expr = std::variant<int, Sum>;
struct Sum {
  std::vector<Expr> terms;  // 여기서는 원소가 아직 불완전 타입이다
};

int eval(const Expr& expr);

struct Eval {
  int operator()(int value) const { return value; }
  int operator()(const Sum& sum) const {
    int total = 0;
    for (const Expr& term : sum.terms) total += eval(term);
    return total;
  }
};

int eval(const Expr& expr) { return std::visit(Eval{}, expr); }

struct Throws {
  Throws() { throw 1; }
  std::vector<int> data;
};

int main() {
  const Expr expr = Sum{{1, Sum{{2, 3}}, 4}};
  assert(eval(expr) == 10);
  assert(eval(Sum{}) == 0);

  std::variant<int, Throws> value = 1;
  try {
    value.emplace<Throws>();
  } catch (int) {
  }
  // 표준은 "값이 없을 수 있다"고만 한다. 아래는 검증한 두 환경의 결과다.
  assert(value.valueless_by_exception());
  [[maybe_unused]] bool rejected = false;
  try {
    std::visit([](const auto&) {}, value);
  } catch (const std::bad_variant_access&) {
    rejected = true;
  }
  assert(rejected);
}

Eval처럼 이름 있는 함수 객체도 방문자로 쓸 수 있습니다. 깊은 트리에서는 eval과 소멸자가 모두 재귀하므로, 입력의 깊이를 제한하지 않으면 스택이 모자랄 수 있습니다.

뒷부분은 값 없는 상태(valueless by exception)입니다. emplace는 기존 값을 먼저 없애고 새 값을 만듭니다. 그 사이에 예외가 나면 variant가 아무 값도 갖지 않을 수 있습니다. 이 상태를 방문하면 std::bad_variant_access 예외가 납니다. 새 값을 먼저 만든 뒤 예외를 던지지 않는 이동으로 넣으면 피할 수 있습니다.

C++26: 멤버 visit

현재 표준 초안에는 std::visit(f, v) 대신 v.visit(f)로 쓰는 멤버 함수가 있습니다. 이 글을 검증한 표준 라이브러리에는 없어서 발췌로만 싣습니다. 호출 모양만 달라지고 앞의 함정은 그대로입니다.

cpp일부 발췌 · 검증 제외
return shape.visit(overloaded{/* 같은 람다들 */});

정리

  • 타입이 자주 늘면 멤버 가상 함수를, 연산이 자주 늘면 Visitor나 variant를 고릅니다.
  • 새로 만드는 닫힌 값 타입이면 variant로 시작합니다. 이미 상속 계층이 있거나 대안의 정의를 헤더에 드러내기 어려우면 Visitor가 맞습니다.
  • std::visit의 빠뜨림 검사는 암시적 변환과 포괄 람다 앞에서 약해집니다. 산술 타입이 섞이면 컴파일을 멈추는 포괄 람다를 둡니다.
  • 두 자료의 타입으로 갈리는 연산은 다중 visit이 간단하지만, 조합 수를 먼저 셉니다.
  • 예외가 날 수 있는 emplace 뒤에는 값 없는 상태를 생각합니다.

다음 편에서는 반대로 타입 집합이 열려 있을 때, 상속 관계가 없는 타입들을 하나의 값으로 다루는 type erasure를 구현합니다.
