Type Erasure — std::function은 어떻게 동작하나

상속 관계가 없는 타입들을 하나의 값 타입으로 다루는 타입 소거를 직접 구현합니다. 개념·모델 구조로 복사와 이동을 갖춘 Drawable을 만들고, 작은 버퍼 최적화를 넣은 미니 function으로 정렬·수명 규칙을 확인한 뒤, std::function·move_only_function·any의 실제 동작과 비교합니다.

상속 관계가 없는 타입들을 하나의 값 타입으로 다루려면 어떻게 해야 할까요? std::function은 함수 포인터, 람다, 함수 객체를 모두 같은 타입으로 담습니다. 이 글은 그 기법, 타입 소거(type erasure)를 직접 구현합니다. 내부 구조를 알면 std::function이 언제 힙을 쓰는지, 왜 복사할 수 없는 람다를 거절하는지 설명할 수 있습니다.

문제 상황

6편의 그림 편집기를 다시 봅니다. 이번에는 도형의 출처가 여러 곳입니다.

  • 원은 우리 코드이고, 글자는 std::string 그대로 쓰고 싶다. 앞으로 플러그인이 도형을 더할 수도 있다.
  • 6편처럼 대안 목록을 미리 적을 수 없다. 타입 집합이 열려 있다.
  • 표준 타입이나 남의 라이브러리 타입은 우리 베이스 클래스를 상속하게 고칠 수 없다.
  • 실행 취소용으로 캔버스를 통째로 복사하면, 복사본은 원본과 독립이어야 한다.
  • 캔버스를 쓰는 쪽은 포인터와 수명을 신경 쓰지 않고 int처럼 값으로 다루고 싶다.

순진한 구현

먼저 떠오르는 것은 공통 인터페이스입니다. 복사를 위해 가상 clone()을 두고, 상속할 수 없는 std::string에는 어댑터 클래스를 씁니다.

cpp컴파일 검증됨 (g++ 14.2 · clang 18.1, C++20)
#include <cassert>
#include <memory>
#include <sstream>
#include <string>
#include <vector>

struct Shape {
  virtual ~Shape() = default;
  virtual void draw(std::ostream& out) const = 0;
  virtual std::unique_ptr<Shape> clone() const = 0;
};

struct Circle final : Shape {
  explicit Circle(double radius) : r(radius) {}
  void draw(std::ostream& out) const override { out << "circle(" << r << ")"; }
  std::unique_ptr<Shape> clone() const override { return std::make_unique<Circle>(*this); }
  double r;
};

// std::string은 Shape를 상속하게 고칠 수 없으므로 감싸는 클래스를 따로 만든다.
struct TextAdapter final : Shape {
  explicit TextAdapter(std::string s) : text(std::move(s)) {}
  void draw(std::ostream& out) const override { out << "text(" << text << ")"; }
  std::unique_ptr<Shape> clone() const override { return std::make_unique<TextAdapter>(*this); }
  std::string text;
};

class Canvas {
 public:
  Canvas() = default;
  Canvas(const Canvas& other) {  // 원소마다 clone()을 불러 깊게 복사한다
    for (const auto& s : other.shapes_) shapes_.push_back(s->clone());
  }
  Canvas& operator=(const Canvas& other) {
    Canvas tmp(other);
    shapes_.swap(tmp.shapes_);
    return *this;
  }
  void add(std::unique_ptr<Shape> s) { shapes_.push_back(std::move(s)); }
  Shape& at(std::size_t i) { return *shapes_.at(i); }
  std::string render() const {
    std::ostringstream out;
    for (const auto& s : shapes_) { s->draw(out); out << ' '; }
    return out.str();
  }

 private:
  std::vector<std::unique_ptr<Shape>> shapes_;
};

int main() {
  Canvas canvas;
  canvas.add(std::make_unique<Circle>(1.5));
  canvas.add(std::make_unique<TextAdapter>("hi"));

  const Canvas snapshot = canvas;
  dynamic_cast<Circle&>(canvas.at(0)).r = 9;  // 원본만 바꾼다
  assert(canvas.render() == "circle(9) text(hi) ");
  assert(snapshot.render() == "circle(1.5) text(hi) ");
}

동작은 합니다. 하지만 비용이 사용하는 쪽에 흩어져 있습니다.

  • 상속할 수 없는 타입마다 어댑터 클래스를 하나씩 써야 한다.
  • 모든 파생 클래스가 같은 모양의 clone()을 반복한다. 하나라도 clone()이 베이스만 복사하면 잘림(slicing)이 생긴다.
  • Canvas의 복사 생성자와 대입 연산자를 직접 써야 한다.
  • 쓰는 쪽이 make_unique와 포인터를 직접 다룬다. 원래 타입의 멤버를 고치려면 dynamic_cast가 필요하다.

어댑터와 clone()은 타입마다 모양이 같습니다. 반복되는 코드는 템플릿이 대신 만들 수 있습니다.

패턴 적용

타입 소거는 세 부분으로 이루어집니다. 이 이름은 Sean Parent의 발표에서 널리 퍼졌습니다.

  • 개념(concept): 지울 타입에 요구하는 연산을 가상 함수로 적은 내부 인터페이스. C++20의 concept 키워드와는 다른 뜻입니다.
  • 모델(model): 실제 타입 T를 값으로 들고 개념을 구현하는 클래스 템플릿. 앞의 어댑터를 컴파일러가 타입마다 만들어 줍니다.
  • 바깥 값 타입: 개념을 가리키는 unique_ptr만 들고, 복사·이동·대입을 값처럼 제공합니다.

상속 없는 타입과 자유 함수

담을 타입은 베이스 클래스 대신 draw(x, out)이라는 자유 함수만 제공하면 됩니다. std::string에도 붙일 수 있습니다.

cpp컴파일 검증됨 (g++ 14.2 · clang 18.1, C++20)
#include <cassert>
#include <concepts>
#include <memory>
#include <sstream>
#include <string>
#include <type_traits>
#include <typeinfo>
#include <utility>
#include <vector>

struct Circle {
  double r;
};
void draw(const Circle& c, std::ostream& out) { out << "circle(" << c.r << ")"; }

// 표준 타입도 상속 없이 담을 수 있다.
void draw(const std::string& s, std::ostream& out) { out << "text(" << s << ")"; }

std::string용 draw는 아래 Drawable보다 먼저 선언해야 합니다. 템플릿 안의 draw(value, out)은 정의 위치에서 보이는 이름과, 인자 타입의 이름공간에서 찾는 이름(인자 의존 탐색, ADL)만 찾기 때문입니다. std::string의 이름공간은 std이므로 나중에 선언한 전역 draw는 ADL로 찾지 못합니다. 우리 타입은 같은 이름공간에 draw를 두면 됩니다.

개념과 모델

cpp컴파일 검증됨 (g++ 14.2 · clang 18.1, C++20)
template <class T>
concept DrawableValue = std::copy_constructible<T> &&
    requires(const T& t, std::ostream& out) { draw(t, out); };

class Drawable {
  struct Concept {  // 지울 타입에 요구하는 연산
    virtual ~Concept() = default;
    virtual void draw_(std::ostream& out) const = 0;
    virtual std::unique_ptr<Concept> clone_() const = 0;
    virtual const std::type_info& type_() const noexcept = 0;
  };

  template <class T>
  struct Model final : Concept {  // 타입마다 컴파일러가 만드는 어댑터
    template <class U>
    explicit Model(U&& v) : value(std::forward<U>(v)) {}
    void draw_(std::ostream& out) const override { draw(value, out); }
    std::unique_ptr<Concept> clone_() const override { return std::make_unique<Model>(value); }
    const std::type_info& type_() const noexcept override { return typeid(T); }
    T value;
  };

  std::unique_ptr<Concept> self_;

 public:
  template <class T>
    requires(!std::same_as<std::remove_cvref_t<T>, Drawable>) &&
            DrawableValue<std::remove_cvref_t<T>>
  Drawable(T&& value)
      : self_(std::make_unique<Model<std::remove_cvref_t<T>>>(std::forward<T>(value))) {}

  Drawable(const Drawable& other) : self_(other.self_ ? other.self_->clone_() : nullptr) {}
  Drawable(Drawable&&) noexcept = default;
  Drawable& operator=(const Drawable& other) {
    Drawable tmp(other);  // 복사가 실패해도 *this는 그대로다
    self_ = std::move(tmp.self_);
    return *this;
  }
  Drawable& operator=(Drawable&&) noexcept = default;
  ~Drawable() = default;

  bool has_value() const noexcept { return self_ != nullptr; }
  const std::type_info& type() const noexcept { return self_ ? self_->type_() : typeid(void); }

  friend void draw(const Drawable& d, std::ostream& out) {
    assert(d.self_ && "옮겨진 Drawable은 대입하거나 파괴만 할 수 있다");
    d.self_->draw_(out);
  }
};

구현에서 짚을 곳이 네 군데 있습니다.

  1. 생성자 템플릿의 제약. Drawable b = a;에서 a가 const가 아닌 좌변값이면, T&&(T = Drawable&)가 const Drawable&보다 잘 맞습니다. 제약이 없으면 복사 생성자 대신 이 템플릿이 골라집니다. Model<Drawable>을 만들면서 같은 생성자를 다시 부르므로 무한 재귀로 스택이 넘칩니다. DrawableValue만 두면 이번에는 컴파일 오류입니다. Drawable도 draw를 제공하므로, copy_constructible<Drawable>을 확인하다가 이 생성자의 제약을 다시 확인하게 됩니다. 그래서 same_as 조건을 맨 앞에 둡니다. &&로 이은 제약은 앞에서부터 확인하고, 거짓이 나오면 뒤는 확인하지 않습니다.
  2. 복사 가능 조건. Model::clone_()은 T를 복사합니다. std::copy_constructible을 제약에 넣어, 복사할 수 없는 타입을 생성자 단계에서 거절합니다.
  3. 이동은 포인터만 옮긴다. 이동 생성자는 noexcept입니다. 그래서 std::vector가 재할당할 때 원소를 복사하지 않고 옮깁니다.
  4. 옮겨진 상태. 옮겨진 Drawable은 값이 없습니다. 대입이나 파괴는 할 수 있지만 그리면 안 됩니다. has_value()로 확인합니다.

가상 함수 이름 끝의 _에도 이유가 있습니다. Model 안에서 draw(value, out)을 부를 때, 이름 탐색이 클래스 멤버 draw를 먼저 찾으면 자유 함수를 더 찾지 않습니다. ADL도 일어나지 않습니다.

값처럼 쓰기

cpp컴파일 검증됨 (g++ 14.2 · clang 18.1, C++20)
// 테스트용: 복사 횟수를 센다. Drawable보다 나중에 선언해도 ADL로 draw를 찾는다.
struct Counted {
  static inline int copies = 0;
  int id;
  explicit Counted(int i) : id(i) {}
  Counted(const Counted& o) : id(o.id) { ++copies; }
  Counted(Counted&&) noexcept = default;
};
void draw(const Counted& c, std::ostream& out) { out << "counted(" << c.id << ")"; }

struct Sprite {  // 복사할 수 없는 타입
  std::unique_ptr<int> pixels;
};
void draw(const Sprite&, std::ostream& out) { out << "sprite"; }

std::string render(const std::vector<Drawable>& canvas) {
  std::ostringstream out;
  for (const auto& d : canvas) { draw(d, out); out << ' '; }
  return out.str();
}

int main() {
  std::vector<Drawable> canvas;
  canvas.emplace_back(Counted{7});
  canvas.emplace_back(Circle{1.5});
  canvas.emplace_back(std::string{"hi"});
  assert(render(canvas) == "counted(7) circle(1.5) text(hi) ");
  assert(Counted::copies == 0);  // 재할당 두 번 동안 옮기기만 했다

  const std::vector<Drawable> snapshot = canvas;  // 기본 복사 = 깊은 복사
  assert(Counted::copies == 1);
  canvas[0] = Circle{9};  // 원본만 바꾼다
  assert(render(canvas) == "circle(9) circle(1.5) text(hi) ");
  assert(render(snapshot) == "counted(7) circle(1.5) text(hi) ");

  Drawable a = Counted{1};
  Drawable b = a;  // const가 아닌 좌변값: 복사 생성자가 골라져야 한다
  assert(b.type() == typeid(Counted));

  Drawable c = std::move(b);
  assert(!b.has_value() && c.type() == typeid(Counted));
  const Drawable empty = b;  // 값이 없는 것도 복사할 수 있다
  assert(!empty.has_value() && empty.type() == typeid(void));
  b = c;  // 옮겨진 값에 다시 대입할 수 있다
  assert(b.type() == typeid(Counted));

  static_assert(!std::is_constructible_v<Drawable, Sprite>);
  static_assert(std::is_nothrow_move_constructible_v<Drawable>);
}

Canvas, 어댑터, 복사 생성자가 모두 사라졌습니다. vector의 기본 복사가 그대로 깊은 복사입니다. Counted와 Sprite는 Drawable보다 나중에 정의했고, Drawable은 이 타입들을 모릅니다.

작은 버퍼 최적화

Drawable은 객체마다 힙 할당을 한 번 합니다. 작은 람다 하나에도 할당하면 비쌉니다. 그래서 std::function 같은 타입은 객체 안에 작은 버퍼를 두고, 담을 값이 버퍼에 맞으면 그 자리에 만듭니다. 이를 작은 버퍼 최적화(SBO, small buffer optimization)라고 합니다.

아래는 이동만 되는 미니 function입니다. 이번에는 가상 함수 대신 함수 포인터 표를 직접 만듭니다. 핵심은 버퍼에 넣는 조건입니다.

  • 크기와 정렬이 버퍼에 맞아야 한다.
  • 이동 생성자가 noexcept여야 한다. 래퍼의 이동이 noexcept이므로, 버퍼 안 객체를 옮기다 예외가 나면 갈 곳이 없다.
  • 버퍼 안 객체는 바이트 복사로 옮기지 않는다. 자기 멤버를 가리키는 포인터가 있으면 옛 주소를 계속 가리키기 때문이다. 이동 생성자로 새 버퍼에 만들고 옛 객체를 파괴한다.
cpp컴파일 검증됨 (g++ 14.2 · clang 18.1, C++20)
#include <array>
#include <cassert>
#include <concepts>
#include <cstddef>
#include <functional>
#include <new>
#include <type_traits>
#include <utility>

template <class Sig>
class UniqueFunction;

template <class R, class... Args>
class UniqueFunction<R(Args...)> {
  static constexpr std::size_t kSize = 4 * sizeof(void*);
  static constexpr std::size_t kAlign = alignof(std::max_align_t);

  template <class F>
  static constexpr bool fits_inline =
      sizeof(F) <= kSize && alignof(F) <= kAlign && std::is_nothrow_move_constructible_v<F>;

  struct VTable {
    R (*invoke)(void* obj, Args&&... args);
    void* (*relocate)(void* from, void* buffer) noexcept;  // 버퍼에 있을 때만 쓴다
    void (*destroy)(void* obj) noexcept;
    bool in_buffer;
  };

  template <class F>
  static constexpr VTable vtable_for{
      [](void* obj, Args&&... args) -> R {
        return std::invoke(*static_cast<F*>(obj), std::forward<Args>(args)...);
      },
      [](void* from, void* buffer) noexcept -> void* {
        F* src = static_cast<F*>(from);
        F* dst = ::new (buffer) F(std::move(*src));
        src->~F();
        return dst;
      },
      [](void* obj) noexcept {
        if constexpr (fits_inline<F>) static_cast<F*>(obj)->~F();
        else delete static_cast<F*>(obj);
      },
      fits_inline<F>};

  alignas(kAlign) std::byte buffer_[kSize];
  void* obj_ = nullptr;  // placement new가 돌려준 포인터를 그대로 들고 있는다
  const VTable* vt_ = nullptr;

  void take(UniqueFunction& other) noexcept {
    if (!other.vt_) return;
    vt_ = other.vt_;
    obj_ = vt_->in_buffer ? vt_->relocate(other.obj_, buffer_) : other.obj_;
    other.vt_ = nullptr;
    other.obj_ = nullptr;
  }
  void reset() noexcept {
    if (vt_) vt_->destroy(obj_);
    vt_ = nullptr;
    obj_ = nullptr;
  }

 public:
  UniqueFunction() = default;

  template <class F>
    requires(!std::same_as<std::remove_cvref_t<F>, UniqueFunction>) &&
            std::is_invocable_r_v<R, std::decay_t<F>&, Args...>
  UniqueFunction(F&& f) {
    using D = std::decay_t<F>;
    if constexpr (fits_inline<D>) obj_ = ::new (static_cast<void*>(buffer_)) D(std::forward<F>(f));
    else obj_ = new D(std::forward<F>(f));
    vt_ = &vtable_for<D>;
  }
  UniqueFunction(UniqueFunction&& other) noexcept { take(other); }
  UniqueFunction& operator=(UniqueFunction&& other) noexcept {
    if (this != &other) {
      reset();
      take(other);
    }
    return *this;
  }
  ~UniqueFunction() { reset(); }

  explicit operator bool() const noexcept { return vt_ != nullptr; }
  bool in_buffer() const noexcept { return obj_ == static_cast<const void*>(buffer_); }
  R operator()(Args... args) {
    assert(vt_);
    return vt_->invoke(obj_, std::forward<Args>(args)...);
  }
};

// 테스트용: 자기 멤버를 가리키고, 살아 있는 개수를 센다.
struct SelfRef {
  static inline int alive = 0;
  int value;
  int* self = &value;
  explicit SelfRef(int v) : value(v) { ++alive; }
  SelfRef(SelfRef&& o) noexcept : value(o.value) { ++alive; }
  SelfRef(const SelfRef&) = delete;
  ~SelfRef() { --alive; }
  int operator()() {
    assert(self == &value);  // 바이트 복사로 옮겼다면 옛 주소를 가리킨다
    return *self;
  }
};

struct alignas(32) Wide {  // 크기는 버퍼에 맞지만 정렬 요구가 더 크다
  int v = 5;
  int operator()() const { return v; }
};

struct MayThrow {
  MayThrow() = default;
  MayThrow(MayThrow&&) {}  // noexcept가 아니다
  int operator()() const { return 1; }
};

int main() {
  {
    UniqueFunction<int()> f = SelfRef{42};
    assert(f.in_buffer());
    assert(SelfRef::alive == 1);  // 임시 객체는 이미 파괴되었다
    UniqueFunction<int()> g = std::move(f);
    assert(!f && g && g.in_buffer());
    assert(SelfRef::alive == 1);  // 옮긴 뒤에도 하나뿐이다
    assert(g() == 42);
    f = std::move(g);  // 다시 옮겨도 자기 참조가 맞다
    assert(f() == 42);
  }
  assert(SelfRef::alive == 0);  // 파괴는 정확히 한 번

  std::array<long, 8> big{};
  big[7] = 7;
  UniqueFunction<long()> heavy = [big] { return big[7]; };
  assert(!heavy.in_buffer());  // 64바이트 캡처는 힙으로
  UniqueFunction<long()> moved = std::move(heavy);  // 힙 객체는 포인터만 옮긴다
  assert(moved() == 7);

  UniqueFunction<int()> wide = Wide{};
  static_assert(sizeof(Wide) <= 4 * sizeof(void*) && alignof(Wide) > alignof(std::max_align_t));
  assert(!wide.in_buffer());  // 정렬 요구가 버퍼보다 크면 힙으로
  assert(wide() == 5);
  static_assert(alignof(UniqueFunction<int()>) == alignof(std::max_align_t));

  UniqueFunction<int()> may_throw = MayThrow{};
  assert(!may_throw.in_buffer());  // 이동이 예외를 던질 수 있으면 힙으로
  assert(may_throw() == 1);

  UniqueFunction<int(int, int)> add = [](int a, int b) { return a + b; };
  assert(add.in_buffer() && add(2, 3) == 5);
}

obj_에는 placement new가 돌려준 포인터를 그대로 둡니다. 버퍼 주소에서 다시 계산하면 std::launder가 필요합니다. 힙에 둔 객체는 포인터만 옮기므로 이동 조건이 없습니다.

타입 소거는 쓰는 쪽에 상속과 포인터를 숨기는 대신, 그 비용을 라이브러리 작성자가 집니다. 개념·모델·복사·이동·SBO를 한 번 바르게 써야 합니다. 호출은 가상 함수나 함수 포인터를 거치므로, 컴파일러가 대상을 모르면 인라인하지 못합니다. 담긴 타입은 지워졌으므로, 개념에 적지 않은 연산은 쓸 수 없습니다.

Drawable의 값은 만든 뒤 바뀌지 않습니다. 이럴 때는 unique_ptr 대신 shared_ptr<const Concept>로 모델을 공유해도 값 의미론이 유지됩니다. 복사는 참조 카운트 증가로 줄지만, 원자적 카운트 비용이 생깁니다.

C++ Core Guidelines T.49도 가능하면 타입 소거를 피하라고 권합니다. 다음 경우에는 쓰지 않습니다.

  • 타입 집합이 닫혀 있으면 6편의 std::variant가 낫습니다. 힙 할당과 간접 호출이 없습니다.
  • 타입을 빌드할 때 정할 수 있으면 함수 템플릿이나 2편의 정책 클래스로 충분합니다.
  • 호출하는 동안만 빌려 쓰는 콜백이라면 소유할 필요가 없습니다. 템플릿 매개변수나 아래의 function_ref가 맞습니다.
  • 상속 계층이 이미 있고 값 의미론이 필요 없다면 unique_ptr<Base>로 충분합니다.

현대 C++ 대안

std::function: 복사 가능한 대상만

std::function도 같은 구조입니다. 다만 std::function 자체가 복사 가능해야 하므로, 담을 대상도 복사할 수 있어야 합니다. unique_ptr를 캡처한 람다는 거절됩니다.

cpp컴파일 오류 예시
#include <functional>
#include <memory>

int main() {
  std::function<int()> f = [p = std::make_unique<int>(1)] { return *p; };
  return f();
}

g++ 14와 clang 18(libstdc++ 14) 모두 std::function target must be copy-constructible이라는 정적 단언으로 실패합니다. 담긴 대상의 타입은 target_type()으로 확인하고, target<T>()로 꺼냅니다. 타입이 다르면 nullptr입니다.

SBO 크기는 표준이 정하지 않습니다. 표준은 작은 대상에 동적 할당을 피하라고 권고만 합니다. 64비트 리눅스의 libstdc++ 14에서 operator new 호출 수를 세어 보면 다음과 같습니다.

담은 대상std::functionstd::move_only_functionstd::any
포인터 1개를 캡처한 람다(8바이트)할당 없음할당 없음할당 없음
포인터 2개(16바이트)할당 없음할당 없음1회

libstdc++의 std::function은 대상이 trivially copyable이고 16바이트 이하일 때만 버퍼에 둡니다. move_only_function은 이 글의 미니 구현과 같은 기준입니다. 크기와 정렬이 맞고 noexcept로 이동할 수 있으면 버퍼에 둡니다. 표준에도 이 조건이 있습니다. std::any는 규정으로, move_only_function과 C++26 copyable_function은 주석으로 적습니다. 다른 표준 라이브러리는 기준이 다르므로, 할당이 중요하면 직접 재야 합니다.

C++23: std::move_only_function

위에서 만든 UniqueFunction을 표준으로 만든 것이 std::move_only_function입니다. 이동만 되는 대상을 담고, const·noexcept 한정자를 시그니처에 적을 수 있습니다. 한정자와 const의 관계는 2편에서 다뤘습니다.

cpp컴파일 검증됨 (g++ 14.2 · clang 18.1, C++23)
#include <cassert>
#include <functional>
#include <memory>
#include <type_traits>
#include <utility>

int main() {
  std::move_only_function<int() const> f = [p = std::make_unique<int>(1)] { return *p; };
  static_assert(!std::is_copy_constructible_v<decltype(f)>);

  auto g = std::move(f);
  assert(g() == 1);
}

C++17: std::any

std::any는 복사·이동·파괴·타입 확인만 남기고 모든 연산을 지운 타입 소거입니다. 값을 쓰려면 원래 타입을 알고 any_cast로 꺼내야 합니다. 연산을 함께 지우는 Drawable과 반대 끝에 있습니다.

cpp컴파일 검증됨 (g++ 14.2 · clang 18.1, C++20)
#include <any>
#include <cassert>
#include <string>
#include <typeinfo>

int main() {
  std::any box = std::string{"hi"};
  assert(box.type() == typeid(std::string));
  assert(std::any_cast<std::string&>(box) == "hi");
  assert(std::any_cast<int>(&box) == nullptr);  // 타입이 다르면 nullptr

  box = 42;
  assert(std::any_cast<int>(box) == 42);
}

C++26: function_ref와 copyable_function

작업 초안에는 두 타입이 더 있습니다. 검증한 표준 라이브러리에는 없어 발췌로만 싣습니다.

cpp일부 발췌 · 검증 제외
// 소유하지 않는다. 호출하는 동안 대상이 살아 있어야 한다.
void for_each_shape(std::function_ref<void(const Drawable&)> visit);

// std::function처럼 복사되면서 const·noexcept 한정자를 지원한다.
std::copyable_function<int() const> f = [] { return 1; };

function_ref는 함수 포인터 하나와 대상을 가리키는 값 하나만 들고, 할당 없이 대상을 가리킵니다. 대신 대상의 수명을 책임지지 않으므로, 저장해 두고 나중에 부르면 안 됩니다.

정리

  • 타입 집합이 열려 있고, 쓰는 쪽에 상속과 포인터를 숨기고 싶을 때 타입 소거를 고릅니다.
  • 구조는 개념(가상 인터페이스), 모델(T를 담는 클래스 템플릿), 바깥 값 타입 세 부분입니다. 생성자 템플릿은 자기 자신을 제외하도록 제약합니다.
  • SBO는 크기·정렬·noexcept 이동 조건을 모두 확인합니다. 버퍼 안 객체는 바이트 복사가 아니라 이동 생성으로 옮깁니다.
  • 호출 하나만 지우면 되면 std::function이나 std::move_only_function을, 빌려 쓰기만 하면 템플릿이나 function_ref를 씁니다.
  • 타입이 닫혀 있거나 빌드할 때 정해지면 타입 소거 대신 variant나 템플릿을 씁니다.
