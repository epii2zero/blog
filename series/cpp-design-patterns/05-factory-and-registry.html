Factory·Abstract Factory — 등록 기반 팩토리

switch에 몰린 생성 코드를 등록 기반 팩토리로 바꿉니다. 함께 쓸 객체를 한 벌로 만드는 Abstract Factory, 여러 파일의 자기 등록, 정적 초기화 순서 문제와 링커가 등록 코드를 빼는 문제를 예제로 확인하고, 명시적 등록과 constexpr 표까지 비교해 고르는 기준을 정리합니다.

새 타입을 추가할 때 기존 생성 코드를 고치지 않으려면 어떻게 해야 할까요? 이 글은 if와 switch에 흩어진 생성 코드를 "이름 → 생성 함수" 표로 옮깁니다. 그 표를 여러 파일에서 스스로 채우게 할 때 만나는 정적 초기화 순서 문제와 링크 문제도 다룹니다. 다 읽고 나면 명시적 등록, 자기 등록, 컴파일 시점 표 가운데 무엇을 쓸지 고를 수 있습니다.

문제 상황

레코드(문자열 필드의 목록)를 파일로 내보내고 다시 읽는 도구를 만든다고 해 봅시다. 형식은 설정 파일에 적힌 이름으로 고릅니다.

  • 설정의 "csv", "tsv" 같은 문자열로 쓰기 객체(Writer)와 읽기 객체(Reader)를 만든다.
  • 쓴 형식 그대로 읽을 수 있어야 한다. CSV로 쓰고 TSV로 읽는 조합은 나오면 안 된다.
  • 새 형식을 추가할 때 기존 생성 함수를 고치지 않는다.
  • 모르는 이름은 호출한 쪽에서 처리하고, 같은 이름을 두 번 등록하면 바로 드러나야 한다.

만든 객체는 호출한 쪽이 소유합니다. 1편에서처럼 생성 함수는 std::unique_ptr를 돌려줍니다.

순진한 구현

먼저 두 인터페이스와 구현입니다. 예제를 짧게 하려고 필드에는 구분자가 없다고 가정합니다.

cpp컴파일 검증됨 (g++ 14.2 · clang 18.1, C++20)
#include <cassert>
#include <functional>
#include <map>
#include <memory>
#include <stdexcept>
#include <string>
#include <string_view>
#include <utility>
#include <vector>

using Record = std::vector<std::string>;

class Writer {
 public:
  virtual ~Writer() = default;
  virtual std::string write(const Record& record) const = 0;
};

class Reader {
 public:
  virtual ~Reader() = default;
  virtual Record read(std::string_view line) const = 0;
};

class DelimitedWriter final : public Writer {
 public:
  explicit DelimitedWriter(char delimiter) : delimiter_(delimiter) {}
  std::string write(const Record& record) const override {
    std::string line;
    for (std::size_t i = 0; i < record.size(); ++i) {
      if (i != 0) line += delimiter_;
      line += record[i];
    }
    return line;
  }

 private:
  char delimiter_;
};

class DelimitedReader final : public Reader {
 public:
  explicit DelimitedReader(char delimiter) : delimiter_(delimiter) {}
  Record read(std::string_view line) const override {
    Record record;
    for (;;) {
      const std::size_t end = line.find(delimiter_);
      record.emplace_back(line.substr(0, end));
      if (end == std::string_view::npos) return record;
      line.remove_prefix(end + 1);
    }
  }

 private:
  char delimiter_;
};

가장 먼저 떠오르는 생성 코드는 이름을 차례로 비교하는 것입니다. TSV를 나중에 추가했다고 해 봅시다.

cpp컴파일 검증됨 (g++ 14.2 · clang 18.1, C++20)
std::unique_ptr<Writer> make_writer_naive(std::string_view name) {
  if (name == "csv") return std::make_unique<DelimitedWriter>(',');
  if (name == "tsv") return std::make_unique<DelimitedWriter>('\t');
  return nullptr;
}

std::unique_ptr<Reader> make_reader_naive(std::string_view name) {
  if (name == "csv") return std::make_unique<DelimitedReader>(',');
  return nullptr;  // "tsv"를 빠뜨렸다
}

void check_naive() {
  assert(make_writer_naive("tsv") != nullptr);
  assert(make_reader_naive("tsv") == nullptr);  // 쓸 수는 있지만 읽을 수 없다
  // 이름을 따로 넘기므로 서로 다른 형식도 짝이 된다.
  [[maybe_unused]] const std::string line = make_writer_naive("tsv")->write({"kim", "42"});
  assert(make_reader_naive("csv")->read(line) == Record{"kim\t42"});  // 필드가 하나가 됐다
}

형식 하나를 추가하려면 함수 두 개를 고쳐야 하고, 한쪽을 빠뜨려도 컴파일됩니다. 짝이 맞지 않는 Writer와 Reader도 막지 못합니다. 이름 목록을 얻을 방법도 따로 만들어야 합니다.

다만 switch 자체가 나쁜 것은 아닙니다. 종류가 enum class로 닫혀 있고 default를 쓰지 않으면, 빠뜨린 값을 -Wswitch 경고로 찾을 수 있습니다. 여기서는 이름이 실행 중에 들어오고 종류가 계속 늘어난다는 점이 다릅니다.

패턴 적용

문제를 둘로 나눕니다. 짝이 맞는 객체를 만드는 일은 Abstract Factory가, 이름으로 고르는 일은 레지스트리(registry)가 맡습니다.

짝을 한 벌로 묶기: Abstract Factory

Abstract Factory는 함께 써야 하는 객체들을 만드는 인터페이스입니다. 객체 하나를 만드는 가상 함수는 Factory Method라고 부릅니다. 아래 Format은 Factory Method 두 개를 가진 Abstract Factory입니다.

cpp컴파일 검증됨 (g++ 14.2 · clang 18.1, C++20)
class Format {
 public:
  virtual ~Format() = default;
  virtual std::unique_ptr<Writer> make_writer() const = 0;
  virtual std::unique_ptr<Reader> make_reader() const = 0;
};

class DelimitedFormat final : public Format {
 public:
  explicit DelimitedFormat(char delimiter) : delimiter_(delimiter) {}
  std::unique_ptr<Writer> make_writer() const override { return std::make_unique<DelimitedWriter>(delimiter_); }
  std::unique_ptr<Reader> make_reader() const override { return std::make_unique<DelimitedReader>(delimiter_); }

 private:
  char delimiter_;
};

이제 형식 이름은 한 번만 고릅니다. 같은 Format에서 나온 Writer와 Reader는 구분자가 같습니다. 새 형식이 make_reader를 빠뜨리면 추상 클래스로 남아 객체를 만들 수 없습니다. 순진한 구현에서 놓친 실수가 컴파일 오류로 바뀝니다.

이름으로 고르기: 레지스트리

레지스트리는 이름과 생성 함수를 짝지은 표입니다. 새 형식은 표에 한 줄을 더하는 것으로 끝나고, create는 바뀌지 않습니다.

cpp컴파일 검증됨 (g++ 14.2 · clang 18.1, C++20)
class FormatRegistry {
 public:
  using Creator = std::function<std::unique_ptr<Format>()>;

  void add(std::string name, Creator creator) {
    if (!creator) throw std::invalid_argument("empty creator: " + name);
    const auto [it, inserted] = creators_.try_emplace(std::move(name), std::move(creator));
    if (!inserted) throw std::logic_error("duplicate format: " + it->first);
  }

  // 모르는 이름이면 nullptr. 오류로 볼지 기본값을 쓸지는 호출한 쪽이 정한다.
  std::unique_ptr<Format> create(std::string_view name) const {
    const auto it = creators_.find(name);
    return it == creators_.end() ? nullptr : it->second();
  }

  std::vector<std::string> names() const {
    std::vector<std::string> result;
    for (const auto& entry : creators_) result.push_back(entry.first);
    return result;
  }

 private:
  std::map<std::string, Creator, std::less<>> creators_;
};

설계에서 고른 것은 네 가지입니다.

  • 객체가 아니라 생성 함수를 저장합니다. 요청할 때마다 새 객체가 생기고, 소유자는 호출한 쪽입니다.
  • 생성 함수는 std::function입니다. 클래스마다 하나가 아니라 설정마다 하나를 등록할 수 있습니다. CSV와 TSV는 같은 클래스에 구분자만 다르게 준 두 항목입니다.
  • 중복은 예외로 알립니다. creators_[name] = …처럼 쓰면 나중 등록이 앞의 것을 조용히 덮어씁니다.
  • std::less<>로 비교합니다. 이런 비교자를 쓰면 find가 std::string_view를 그대로 받습니다(C++14). 순서가 있는 std::map이라 names()의 결과도 등록 순서와 무관합니다. 항목이 아주 많으면 std::unordered_map을 쓸 수 있지만, string_view로 찾으려면 C++20의 투명한 해시와 std::equal_to<>가 함께 필요합니다.

등록은 평범한 함수로 시작합니다. 이를 명시적 등록(explicit registration)이라고 부르겠습니다.

cpp컴파일 검증됨 (g++ 14.2 · clang 18.1, C++20)
void register_builtin_formats(FormatRegistry& registry) {
  registry.add("csv", [] { return std::make_unique<DelimitedFormat>(','); });
  registry.add("tsv", [] { return std::make_unique<DelimitedFormat>('\t'); });
}

int main() {
  check_naive();

  FormatRegistry registry;  // 전역이 아니라 지역 객체다
  register_builtin_formats(registry);
  assert((registry.names() == std::vector<std::string>{"csv", "tsv"}));

  [[maybe_unused]] const Record record{"kim", "", "42"};
  for ([[maybe_unused]] const std::string& name : registry.names()) {
    const std::unique_ptr<Format> format = registry.create(name);
    assert(format != nullptr);
    assert(format->make_reader()->read(format->make_writer()->write(record)) == record);
  }
  assert(registry.create("tsv")->make_writer()->write(record) == "kim\t\t42");
  assert(registry.create("csv") != registry.create("csv"));  // 매번 새 객체
  assert(registry.create("xml") == nullptr);

  // 새 형식: 기존 코드는 고치지 않았다.
  registry.add("pipe", [] { return std::make_unique<DelimitedFormat>('|'); });
  assert(registry.create("pipe")->make_writer()->write({"a", "b"}) == "a|b");

  [[maybe_unused]] bool rejected = false;
  try {
    registry.add("csv", [] { return std::make_unique<DelimitedFormat>(';'); });
  } catch (const std::logic_error&) {
    rejected = true;
  }
  assert(rejected);
  assert(registry.create("csv")->make_writer()->write({"a", "b"}) == "a,b");  // 원래 등록이 남는다

  rejected = false;
  try {
    registry.add("broken", nullptr);
  } catch (const std::invalid_argument&) {
    rejected = true;
  }
  assert(rejected && registry.create("broken") == nullptr);
}

레지스트리가 지역 객체라서 테스트마다 새로 만들 수 있고, 초기화 순서 문제도 없습니다. 새 형식을 더할 때 고치는 곳은 register_builtin_formats 한 곳뿐입니다. 많은 프로그램은 여기서 멈추는 것이 좋습니다.

여러 파일의 자기 등록

그 한 곳도 고치고 싶지 않다면, 형식마다 자기 파일에서 스스로 등록하게 할 수 있습니다. 이를 자기 등록(self-registration)이라고 합니다. 네임스페이스 범위 객체의 생성자가 등록을 맡습니다. 여기서는 초기화 문제만 보기 위해 Format을 함수 하나짜리로 줄입니다.

cpp컴파일 검증됨 (g++ 14.2 · clang 18.1, C++20)
#pragma once
#include <functional>
#include <map>
#include <memory>
#include <stdexcept>
#include <string>
#include <string_view>
#include <utility>

struct Format {
  virtual ~Format() = default;
  virtual std::string join(std::string_view a, std::string_view b) const = 0;
};

class FormatRegistry {
 public:
  using Creator = std::function<std::unique_ptr<Format>()>;
  void add(std::string name, Creator creator) {
    const auto [it, inserted] = creators_.try_emplace(std::move(name), std::move(creator));
    if (!inserted) throw std::logic_error("duplicate format: " + it->first);
  }
  std::unique_ptr<Format> create(std::string_view name) const {
    const auto it = creators_.find(name);
    return it == creators_.end() ? nullptr : it->second();
  }

 private:
  std::map<std::string, Creator, std::less<>> creators_;
};

FormatRegistry& format_registry();  // 정의는 registry.cpp

struct FormatRegistrar {
  FormatRegistrar(std::string name, FormatRegistry::Creator creator) {
    format_registry().add(std::move(name), std::move(creator));
  }
};
cpp컴파일 검증됨 (g++ 14.2 · clang 18.1, C++20)
#include "format.h"

namespace {
class Csv final : public Format {
  std::string join(std::string_view a, std::string_view b) const override {
    return std::string(a) + "," + std::string(b);
  }
};
[[maybe_unused]] const FormatRegistrar registrar{"csv", [] { return std::make_unique<Csv>(); }};
}  // namespace
cpp컴파일 검증됨 (g++ 14.2 · clang 18.1, C++20)
#include "format.h"

namespace {
class Tsv final : public Format {
  std::string join(std::string_view a, std::string_view b) const override {
    return std::string(a) + "\t" + std::string(b);
  }
};
[[maybe_unused]] const FormatRegistrar registrar{"tsv", [] { return std::make_unique<Tsv>(); }};
}  // namespace
cpp컴파일 검증됨 (g++ 14.2 · clang 18.1, C++20)
#include "format.h"

FormatRegistry& format_registry() {
  static FormatRegistry registry;  // 처음 부를 때 만들어진다
  return registry;
}
cpp컴파일 검증됨 (g++ 14.2 · clang 18.1, C++20)
#include <cassert>

#include "format.h"

int main() {
  [[maybe_unused]] const auto csv = format_registry().create("csv");
  [[maybe_unused]] const auto tsv = format_registry().create("tsv");
  assert(csv != nullptr && csv->join("a", "b") == "a,b");
  assert(tsv != nullptr && tsv->join("a", "b") == "a\tb");
}

main.cpp는 Csv도 Tsv도 모릅니다. 형식을 추가할 때 고칠 C++ 코드는 새 파일 하나입니다(빌드 목록에는 넣어야 합니다). 대신 새 문제가 셋 생깁니다.

첫째, 초기화 순서입니다. 레지스트리를 네임스페이스 범위 변수로 두면 다음과 같습니다.

cpp일부 발췌 · 검증 제외
// registry.cpp
FormatRegistry g_registry;  // csv.cpp의 registrar보다 먼저 만들어진다는 보장이 없다

한 번역 단위(translation unit) 안에서는 보통 변수가 정의된 순서대로 초기화됩니다. 서로 다른 번역 단위 사이에는 정해진 순서가 없습니다. registrar가 먼저 초기화되면 아직 만들어지지 않은 std::map에 원소를 넣게 되어 미정의 동작(UB, undefined behavior)입니다. 이를 정적 초기화 순서 문제(static initialization order fiasco)라고 합니다.

함수 안의 정적 변수는 실행 흐름이 선언에 처음 닿을 때 초기화됩니다. 그래서 누가 먼저 format_registry()를 부르든 레지스트리가 먼저 만들어집니다. 위 예제를 csv.cpp, registry.cpp, main.cpp 순서를 바꿔 링크해도 결과가 같습니다.

소멸 순서도 맞습니다. registrar의 생성자가 끝나기 전에 레지스트리 생성이 끝나므로, 소멸은 반대로 registrar가 먼저입니다. 예제의 registrar는 소멸할 때 하는 일이 없지만, 소멸자에서 등록을 지우도록 바꿔도 레지스트리는 아직 살아 있습니다. 그러나 생성자에서 레지스트리를 건드리지 않은 다른 정적 객체가 소멸자에서 레지스트리를 쓰면 이미 사라진 뒤일 수 있습니다. 정적 객체의 소멸자에서는 레지스트리를 쓰지 않습니다.

둘째, 등록이 아예 실행되지 않을 수 있습니다. 원인은 두 층입니다.

  • 표준: 네임스페이스 범위 변수의 동적 초기화를 main 앞에서 할지 뒤로 미룰지는 구현이 정합니다. 미룬다면, 그 번역 단위에서 정의한 (인라인이 아닌) 함수나 변수를 쓰기 전까지만 보장합니다. csv.cpp의 것은 아무도 쓰지 않으므로 이 보장에 기댈 수 없습니다. 이 글의 예제는 검증한 두 컴파일러에서 main 전에 초기화가 끝난다는 동작에 기대고 있습니다.
  • 링커: 정적 라이브러리(.a)에 넣으면 GNU ld 같은 링커는 해결되지 않은 심볼을 정의한 오브젝트 파일만 꺼냅니다. csv.o는 참조되는 심볼이 없으므로 통째로 빠지고, 오류 없이 create("csv")가 nullptr가 됩니다.

링커 문제는 오브젝트 파일을 직접 링크하거나(CMake라면 OBJECT 라이브러리), 해당 라이브러리를 GNU ld의 --whole-archive와 --no-whole-archive 사이에 두면 풀립니다. 이 글의 검증 환경에서 정적 라이브러리로 묶으면 등록이 사라지고, --whole-archive로 돌아오는 것을 확인했습니다. 다른 환경에는 macOS 링커의 -force_load, MSVC의 /WHOLEARCHIVE, CMake 3.24의 $<LINK_LIBRARY:WHOLE_ARCHIVE,…>가 있으며, 이 셋은 이 글에서 실행해 보지 않았습니다. 시작할 때 필요한 이름이 모두 있는지 검사하면 조용한 누락을 막을 수 있습니다.

셋째, 오류와 스레드입니다. main 전에는 예외를 받을 곳이 없습니다. 네임스페이스 범위 변수를 초기화하다 예외가 빠져나가면 std::terminate가 불립니다. 중복 등록이 프로그램을 바로 멈추는 것은 여기서는 원하는 결과지만, 복구할 기회는 없습니다. 또 함수 안 정적 변수의 초기화는 여러 스레드가 동시에 불러도 안전하지만, add까지 안전해지는 것은 아닙니다. 스레드를 만들기 전에 등록을 끝내고, 그 뒤에는 읽기만 합니다. 동적 라이브러리를 실행 중에 불러온다면 별도의 동기화가 필요합니다. 라이브러리를 내리기 전에는 그곳의 생성 함수를 지우고, 만든 객체도 모두 없애야 합니다.

등록 기반 팩토리를 쓰지 말아야 할 때도 있습니다.

  • 만들 타입이 호출하는 곳에서 이미 정해져 있다면 std::make_unique<T>(…)를 바로 씁니다.
  • 종류가 서너 개로 고정이면 enum class와 switch가 짧고, 빠뜨린 값도 경고로 찾습니다.
  • 타입마다 생성 인자가 다르면 한 표에 억지로 맞추지 마세요. 공통 설정 객체를 받게 하거나, 예제처럼 등록할 때 인자를 묶습니다. 그것도 어색하면 같은 팩토리로 다룰 대상이 아닐 수 있습니다.
  • 플러그인 요구가 없는데 자기 등록을 쓰면, 등록 함수 한 줄을 아끼고 초기화·링크 문제를 얻습니다.

현대 C++ 대안

C++17/20: 닫힌 집합은 상수 표로

형식이 빌드할 때 모두 정해진다면 실행 중에 등록할 이유가 없습니다. 이름과 함수 포인터의 constexpr 배열이면 충분합니다. 캡처 없는 람다는 C++17부터 상수식에서 함수 포인터로 바꿀 수 있습니다.

cpp컴파일 검증됨 (g++ 14.2 · clang 18.1, C++20)
#include <array>
#include <cassert>
#include <cstddef>
#include <memory>
#include <string>
#include <string_view>

struct Format {
  virtual ~Format() = default;
  virtual char delimiter() const = 0;
};
struct Csv final : Format {
  char delimiter() const override { return ','; }
};
struct Tsv final : Format {
  char delimiter() const override { return '\t'; }
};

struct Entry {
  std::string_view name;
  std::unique_ptr<Format> (*make)();
};

constexpr std::array formats{
    Entry{"csv", [] { return std::unique_ptr<Format>(std::make_unique<Csv>()); }},
    Entry{"tsv", [] { return std::unique_ptr<Format>(std::make_unique<Tsv>()); }},
};

template <std::size_t N>
constexpr bool unique_names(const std::array<Entry, N>& entries) {
  for (std::size_t i = 0; i < N; ++i)
    for (std::size_t j = i + 1; j < N; ++j)
      if (entries[i].name == entries[j].name) return false;
  return true;
}
static_assert(unique_names(formats));  // 중복은 컴파일 오류다

std::unique_ptr<Format> create(std::string_view name) {
  for (const Entry& entry : formats)
    if (entry.name == name) return entry.make();
  return nullptr;
}

int main() {
  [[maybe_unused]] const auto csv = create("csv");
  [[maybe_unused]] const auto tsv = create("tsv");
  assert(csv != nullptr && csv->delimiter() == ',');
  assert(tsv != nullptr && tsv->delimiter() == '\t');
  assert(create("xml") == nullptr);
}

constexpr 변수는 상수 초기화(constant initialization)됩니다. 상수 초기화는 모든 동적 초기화보다 먼저 일어나므로, 다른 파일의 초기화 코드에서 이 표를 써도 순서 문제가 없습니다. 예제의 람다는 반환 타입을 unique_ptr<Format>으로 맞췄습니다. 함수 포인터는 std::function과 달리 반환 타입이 정확히 같아야 하기 때문입니다.

값은 바뀌어야 하지만 초기화만 컴파일할 때 끝내고 싶다면 C++20의 constinit을 씁니다. 동적 초기화가 필요한 변수에 붙이면 오류가 나므로, 초기화 순서 문제를 컴파일러가 찾아 줍니다.

cpp컴파일 오류 예시
#include <map>
#include <string>

struct Format;
constinit std::map<std::string, Format* (*)()> creators;  // C++20의 map은 상수 초기화할 수 없다

C++17: 상태가 없는 제품은 함수 묶음으로

예제의 Writer와 Reader는 함수가 하나뿐입니다. 이런 제품이라면 클래스 여섯 개 대신 함수 두 개를 담은 값으로 한 벌을 표현할 수 있습니다. 짝을 맞춘다는 Abstract Factory의 목적은 그대로입니다.

cpp컴파일 검증됨 (g++ 14.2 · clang 18.1, C++20)
#include <cassert>
#include <cstddef>
#include <functional>
#include <map>
#include <string>
#include <string_view>
#include <utility>

using Pair = std::pair<std::string, std::string>;

struct Codec {
  std::function<std::string(const Pair&)> write;
  std::function<Pair(std::string_view)> read;
};

Codec delimited(char d) {
  return {
      [d](const Pair& p) { return p.first + d + p.second; },
      [d](std::string_view line) {
        const std::size_t at = line.find(d);
        if (at == std::string_view::npos) return Pair{line, ""};
        return Pair{line.substr(0, at), line.substr(at + 1)};
      },
  };
}

int main() {
  const std::map<std::string, Codec, std::less<>> codecs{{"csv", delimited(',')}, {"tsv", delimited('\t')}};
  for ([[maybe_unused]] const auto& [name, codec] : codecs) assert(codec.read(codec.write({"kim", "42"})) == Pair("kim", "42"));
  assert(codecs.at("csv").write({"a", "b"}) == "a,b");
  assert(codecs.at("tsv").write({"a", "b"}) == "a\tb");
}

여기서는 레지스트리가 생성 함수 대신 Codec 값을 가집니다. 꺼내 쓸 때 복사하거나 참조하면 되고, 호출한 쪽이 힙 객체를 소유하지 않습니다. 대신 컴파일러가 빠뜨린 함수를 찾아 주지 않습니다. 빈 std::function을 부르면 std::bad_function_call 예외가 납니다. 제품에 함수가 여럿이거나 객체마다 상태가 있다면 클래스 쪽이 낫습니다.

정리

  • 팩토리는 호출하는 쪽이 구체 타입을 몰라야 할 때 씁니다. 짝이 맞아야 하는 객체는 Abstract Factory로 한 번에 고릅니다.
  • 열린 집합이면 "이름 → 생성 함수" 레지스트리를 두고, 기본은 명시적 등록으로 시작합니다.
  • 자기 등록은 새 파일만으로 확장해야 할 때 씁니다. 레지스트리는 함수 안 정적 변수로 두고, 링크 방식과 시작할 때의 이름 검사를 함께 정합니다.
  • 함수 안 정적 변수는 초기화 순서만 풀어 줍니다. 등록 실행, 소멸 시점, 동시 등록은 따로 설계합니다.
  • 닫힌 집합이면 switch나 constexpr 표로 순서 문제를 없앱니다.

다음 편에서는 타입 집합이 닫혀 있을 때 객체를 어떻게 다룰지, 클래식 Visitor와 std::variant를 비교합니다.
